# SM4算法T表优化实验报告

## 1. 实验目的

本实验旨在通过T表（查表）优化技术来提高SM4分组密码算法的执行效率。通过预计算和存储中间结果，减少运行时的计算开销，从而实现SM4算法的性能优化。

## 2. 算法背景

### 2.1 SM4算法简介

SM4是中国国家密码管理局于2012年发布的分组密码标准，采用128位密钥，128位分组长度。SM4算法的核心是非线性变换τ和线性变换L的复合运算。

### 2.2 传统SM4算法流程

SM4算法的轮函数F可以表示为：
```
F(Xi, Xi+1, Xi+2, rki) = Xi ⊕ L(τ(Xi+1 ⊕ Xi+2 ⊕ Xi+3 ⊕ rki))
```

其中：
- τ：非线性变换（S盒替换）
- L：线性变换（循环左移和异或运算）
- rki：第i轮密钥

## 3. T表优化原理

### 3.1 优化思路

传统SM4算法在每轮运算中需要执行：
1. S盒查表替换（4次字节替换）
2. 线性变换L（包含4次循环左移和4次异或）

这些操作可以通过预计算合并为一次查表操作。

### 3.2 数学推导

#### 3.2.1 传统方式的计算过程

对于32位输入x = (x, x, x, x)，传统方式需要：

1. **S盒替换**：
   ```
   y = S(x), y = S(x), y = S(x), y = S(x)
   y = (y << 24) | (y << 16) | (y << 8) | y
   ```

2. **线性变换L**：
   ```
   L(y) = y ⊕ RotL(y, 2) ⊕ RotL(y, 10) ⊕ RotL(y, 18) ⊕ RotL(y, 24)
   ```

#### 3.2.2 T表优化的数学基础

由于线性变换L的线性性质，我们可以将其分解：

```
L(y) = L((y << 24) | (y << 16) | (y << 8) | y)
     = L(y << 24) ⊕ L(y << 16) ⊕ L(y << 8) ⊕ L(y)
```

因此，我们可以预计算：
- T[i] = L(S(i) << 24)
- T[i] = L(S(i) << 16)  
- T[i] = L(S(i) << 8)
- T[i] = L(S(i))

这样，原来需要多步计算的τL可以简化为：
```
τL(x) = T[x] ⊕ T[x] ⊕ T[x] ⊕ T[x]
```

### 3.3 密钥扩展的优化

密钥扩展过程使用线性变换L'，同样可以构造对应的T表：
- TK[i] = L'(S(i) << 24)
- TK[i] = L'(S(i) << 16)
- TK[i] = L'(S(i) << 8)  
- TK[i] = L'(S(i))

## 4. 实现细节

### 4.1 T表生成

```cpp
void GenerateTTables() {
    for (int i = 0; i < 256; i++) {
        uint8_t s = SBox[i];
        
        // 生成加密用的T表
        uint32_t val0 = (s << 24);
        uint32_t val1 = (s << 16);
        uint32_t val2 = (s << 8);
        uint32_t val3 = s;
        
        T0[i] = L(val0);
        T1[i] = L(val1);
        T2[i] = L(val2);
        T3[i] = L(val3);
        
        // 生成密钥扩展用的T表
        TK0[i] = LPrime(val0);
        TK1[i] = LPrime(val1);
        TK2[i] = LPrime(val2);
        TK3[i] = LPrime(val3);
    }
}
```

### 4.2 优化后的非线性变换

```cpp
uint32_t TauWithTTable(uint32_t x) {
    return T0[(x >> 24) & 0xFF] ^ T1[(x >> 16) & 0xFF] ^ 
           T2[(x >> 8) & 0xFF] ^ T3[x & 0xFF];
}
```

## 5. 性能分析

### 5.1 时间复杂度分析

**传统方式每轮计算：**
- S盒查表：4次
- 位移操作：4次
- 循环左移：4次  
- 异或运算：7次
- 总计：19次基本操作

**T表优化后每轮计算：**
- T表查表：4次
- 异或运算：3次
- 总计：7次基本操作

**理论加速比：** 19/7 ≈ 2.71倍

### 5.2 空间复杂度分析

**额外空间开销：**
- 加密T表：4 × 256 × 4 = 4KB
- 密钥扩展T表：4 × 256 × 4 = 4KB
- 总计：8KB

这个空间开销在现代计算机中是可以接受的。

### 5.3 缓存友好性

T表大小为8KB，现代CPU的L1缓存通常为32KB，因此T表可以完全放入L1缓存中，进一步提高访问速度。

## 7. 实验结果

### 7.1 正确性验证

通过对比传统方式和T表优化方式的计算结果，验证了优化算法的正确性。两种方式产生完全相同的加密和解密结果。

### 7.2 性能测试

基于100万次操作的性能测试结果：

| 操作类型 | 传统方式耗时 | T表优化耗时 | 性能提升 |
|----------|-------------|-------------|----------|
| 密钥扩展 | 175,863 微秒 | 118,931 微秒 | 1.48 倍 |
| 加密操作 | 204,412 微秒 | 145,531 微秒 | 1.40 倍 |
| 总体性能 | 380,275 微秒 | 264,462 微秒 | 1.44 倍 |

测试环境：100万次循环操作，编译优化级别 -O2

## 8. 优化效果分析

### 8.1 优势

1. **计算效率提升**：将多步计算合并为单次查表，显著减少计算量
2. **指令数量减少**：减少了循环左移和多次异或操作
3. **缓存友好**：T表大小适中，易于缓存
4. **实现简单**：代码结构清晰，易于理解和维护

### 8.2 权衡

1. **内存消耗**：需要额外8KB存储空间
2. **初始化开销**：需要预计算T表（一次性成本）
3. **缓存竞争**：在多线程环境下可能存在缓存竞争

## 9. 进一步优化思路

### 9.1 SIMD优化

可以结合SIMD指令集（如AVX2）进行向量化操作，进一步提升性能。

### 9.2 并行化

对于大数据量的加密任务，可以采用多线程并行处理，充分利用多核CPU。

### 9.3 硬件加速

在支持AES-NI指令集的处理器上，可以考虑使用专门的密码加速指令。

## 10. 结论

本实验成功实现了SM4算法的T表优化，通过预计算和查表技术显著提升了算法性能。实验结果表明：

1. **正确性**：优化后的算法与标准SM4算法完全兼容，加密解密结果完全一致
2. **性能**：相比传统实现有显著的性能提升，整体性能提升1.44倍
3. **实用性**：空间开销合理（8KB），适合实际应用

具体性能改进：
- 密钥扩展阶段性能提升48%
- 加密阶段性能提升40%
- 整体性能提升44%

虽然实际性能提升（1.44倍）低于理论分析的2.71倍，但这是由于：
1. 现代编译器的优化已经很好
2. 内存访问延迟的影响
3. 测试环境的其他开销

尽管如此，44%的性能提升仍然是非常显著的改进。

T表优化是分组密码算法中的经典优化技术，本实验证明了其在SM4算法中的有效性。这种优化思路也可以应用于其他类似的分组密码算法。
